// .infoHash
The info hash is the SHA-1 hash of the bencoded info dictionary of torrent.
Concept: We dont hash entire torrent. We only take torrent.info and bencode it again 
and then calculate SHA-1.

Why?
    This is to know which torrent swarm another peer belongs to? it uses the info hash.
    for ex, user a -> hash a, user b -> hash a , so they know they both are downloading same torrent
    SHA-1 : 20 byte
    What Is Its Purpose
    ->Unique Swarm Identifier (Tracker Communication)
        When your client contacts a tracker to ask for peers, it doesn't send the file name or the entire torrent file. It sends this 20-byte info_hash as a parameter:
        The tracker groups all peers sharing or downloading the exact same files under this 20-byte key.
        If two users have the same infoHash, they are part of the exact same download swarm.
    ->Peer Verification (The TCP Handshake)
        When connecting to another peer over TCP, the very first message exchanged is a handshake packet. Both peers send the info_hash:
        If the peer’s infoHash matches yours, the connection is accepted.
        If it doesn't match (for instance, if the peer is downloading something else on that port), the socket is immediately closed.
    ->Data Integrity Guarantee
        Because torrent.info contains the cryptographic hashes of every single piece 
        (torrent.info.pieces), hashing the info dictionary creates a secure root reference 
        (similar to a Merkle root). If a malicious peer tries to feed you modified pieces or 
        alter the file layout, the hashes won't match the infoHash you originally verified

// .pieceHash
    What is pieces in a torrent file? 
        So if torrent is divided into x pieces, then it needs to know whether each piece is correct.
        So when torrent is created, the torrent create calculates SHA-1 of each x piece.
        Each SHA-1 result 20 bytes. so torrent store this hash "concatenated together".
        so x pieces, then x*20 = 20x bytes.
    But why each piece hash is there? 
        Because the peer may send corrupted or unrelated data, so to verify it we need this.
    
    This function extracts the piece hash of every piece.
    As SHA-1 is 20 byte of every piece, we get the pieceIndex*20 for start and start + 20 for 
    its end, which will give the piece hash.
